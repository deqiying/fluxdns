## 目标与边界

在现有进程指标下新增内存分析，分开呈现 OS 实测、已知索引载荷、运行时计数与预算计费。不能把模块估算相加为 RSS，不能以差额推断泄漏、allocator 保留或碎片。

不更改 allocator、缓存权重与规则刷新；不回收内存、清空缓存、重载规则。SQLite 与 allocator 的内存字节保持未采集。

## 实施与验收

- Linux 同轮读取 status 与 smaps_rollup（非原子），字段级可用性；其他平台明确降级。
- 复用进程指标 owner，每 30 秒采 OS 分项；最多一小时、121 份真实趋势，不补零或补造历史。
- 手动完整分析单槽、2 秒预算；超时/取消的 worker 不发布，真实结束才释放槽位。
- 规则只读现有 Arc 索引，去重并区分实际持有位置；已知载荷估算不包含不可证明的内部节点/allocator 开销。
- 接入真实缓存 weight/条目、replay 计费、统计/队列与分片 lease 计数，不以容量上限冒充占用。
- 更新 OpenAPI、生成类型、fixture 与正式组件；保留现有页面风格、时区、错误和可见性轮询约束。
- 通过 parser/共享去重/并发取消/HTTP/前端/契约测试，以及 320–1600px 响应式检查。
- Linux 真实运行核对 proc/API，并验证分析期间 DNS 继续工作；没有相应环境则保留待验收，不以 fixture 代替。
