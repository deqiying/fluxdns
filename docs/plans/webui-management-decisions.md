建议先确认 D-01 至 D-07 的产品与契约方向，以及 D-09 的页面范围；D-08/D-10 可以先确认处理原则。依赖版本、容量保护和性能阈值没有足够证据时，由实施者按本文技术核定表补齐，不要求现在凭经验填写全部数字。

## 3. 产品与契约决策

### D-01 版本与前后端切换

**要决定：** 新版本标识和切换范围，避免旧字段换了含义却继续使用旧版本。

| 子项 | 推荐方案 A | 备选方案及代价 |
| --- | --- | --- |
| 配置版本 | 使用下一 schema 主版本；当前方案以 version 1 为旧基线，本汇总建议新版本为 2 | 指定其他正式版本值；仍需显式区分新旧契约 |
| Management API | 使用新 major，建议 `/api/v2`；schema 文件相应为 `management-api-v2.yaml`，生成入口同批修改 | 额外维护旧 API 兼容会增加转换、测试和退出成本，属于原计划之外的兼容范围 |
| auth 和前端 | setup/login/logout/session 与新版客户端统一切换，未知旧 API 返回明确错误，不回退 SPA HTML | 单独保留旧 auth 路径需要明确版本边界与生命周期，不能无说明混用 |
| 前端页面路径 | 保留 `/dashboard`、`/queries`；其余按模块划分，旧页面仅语义一致时 redirect | 若有必须保留的书签路径，列出具体路径；不存在一一对应的旧页不做错误跳转 |

选择 A 不要求统计 DB schema、详情 layout、缓存格式和 API 使用同一个版本号；它们分别演进。新版本名为待确认建议，当前源码和 OpenAPI 尚未切换。

**确认栏：** 待确认。可回复“D-01 A”，或逐项指定版本/必须保留的路径。
**影响：** BE-01、FE-01、BC-01、FC-01；来源为总计划原 D-01、前端 FE-01。

### D-02 保存、应用与待重启配置

**要决定：** 文件已经保存但运行时未应用时，界面和后续编辑怎么处理。

- **推荐 A：** 区分源配置和运行 revision；展示已应用、已保存待任务边界、已保存需重启、已保存但应用失败。日志待重启时，其他可独立热应用的配置仍可继续生效。
- **备选 B：** 存在待重启差异时阻止后续热应用，要求先通过维护流程重启。实现较简单，但修改日志可能阻断其他配置管理。

两种选择都保留：校验/prepare 失败不覆盖源与运行态，revision 冲突拒绝覆盖，响应丢失先回读确认结果，不盲目重放创建/改名，不自动重启。

A 需要验证“保存视图”和“可应用投影”的一致性。若源码证明无法可靠分离，实施者必须报告并重新确认，不能偷偷退化为 B。listener 无法安全重绑时，建议拒绝本次候选并保留旧入口；若希望允许仅保存待维护，须另明确该交互。

**确认栏：** 待确认；A / B；listener 重绑失败处理：待确认。
**影响：** BE-02/08、FE-02、BC-02/03、FC-02；来源为后端 BE-02 的失败和生效表。

### D-03 资源改名与本期操作范围

**要决定：** 被引用资源改名时是否自动维护引用，以及本期有哪些顶层操作。

- **推荐 A：** 上游、组及其他允许改名资源按旧键定位，在一个完整候选中更新类型化引用；错误时整次候选失败。首期交付图稿已有的列表、新增、编辑。
- **备选 B：** 被引用的资源暂时禁止改名，先由用户调整引用；会限制现有图稿的编辑能力，需要同步调整计划与交互。

客户端 ID 在普通编辑中仍只读，名称可重复；名称不是历史身份。策略规则、组成员、DoH 路由等子项可在所属资源表单中增删改，不等于新增顶层删除 API。

当前计划不包含顶层资源删除、批量删除、记录删除、缓存清空、强制刷新或系统操作按钮。如需要其中任何一项，请明确名称，另补操作确认、引用处理和失败语义，不能从“管理配置”自动推导。

**确认栏：** 待确认；A / B；额外操作需求：待确认，未填写不增加。
**影响：** BE-08、FE-05 至 FE-11、模块提交检查点；来源为总计划 D-03 和范围边界。

### D-04 指标口径与在线客户端

**要决定：** “请求数”和“在线客户端”统计的对象，不只是图表样式。

| 子项 | 推荐方案 | 改选时的影响 |
| --- | --- | --- |
| 请求计数 | 有效 DNS 请求进入正常处理时计一次；缓存/本地/上游失败均计入，不以详情落库量计数 | 若按完成计数，慢请求会改变时间窗口归属，必须调整数据源与说明 |
| 顶部读数 | 最近 60 秒请求数 / 60 为 QPS；最近 600 秒请求数 / 10 为 RPM | 两个既定窗口不能用当前 QPS 乘 60 相互替代 |
| 趋势 | 最近 10 分钟共同时间轴；QPS 用 1 秒桶，RPM 用完整分钟桶 | 其他采样粒度要明确峰值、延迟和降采样语义 |
| 在线客户端 | 最近 60 秒内按原始 ID 去重，无 ID 时按有效 IP；两类 key 域分隔 | 按配置 ID、名称或 IP 一律合并会改变 NAT/共享网段下的数量 |
| 暖机/缺数 | 窗口不足展示 warming/覆盖时长；丢样与基数超限明确标记 | 不把停机或缺数补成正常零流量 |
| 内存 | 两页面都用进程常驻内存，API 字节，页面建议统一用 MiB | 若使用 MB，需一致地采用十进制单位，不能只换标签 |

**确认栏：** 待确认。可整体采纳推荐，或指定计数/采样/显示单位的改动。
**影响：** BE-09、FE-03/11、BC-23、FC-03/14；来源为后端 BE-09。

### D-05 分页、自动刷新与实时缓冲

**主要选择：**

- **推荐 A：** 历史列表采用 opaque cursor 前后翻页，保留页大小，不提供任意页码直跳；总数按后端实际可用结果展示。
- **备选 B：** 保留图稿中的数字页码和任意页跳转。需要补充跨分片定位、深页查询和并发变化的一致性设计及性能验证，不能仅以大 OFFSET 实现后宣称可用。

**其余需要确认的默认行为：**

| 子项 | 子计划已有建议 | 说明 |
| --- | --- | --- |
| 解析记录自动刷新 | 默认关闭，用户开启后订阅 | 可改为默认开启；需明确进入/离开和后台页面的连接成本 |
| 服务指标推送 | 每 1 秒 | 只影响显示更新，不改变 60/600 秒统计窗口 |
| 解析记录推送 | 每 1 秒合批 | 仅推送已提交详情，详情关闭不伪造新记录 |
| 后端 replay | 60 秒、5000 条、8 MiB，先达到者为上限 | 超出或重启后显式 resync，不承诺无限或无损回放 |
| 前端待更新缓冲 | 500 条或 2 MiB，先达到者为上限 | 超出后停止积累正文，提示刷新，不继续声称精确条数 |
| 查阅详情/历史页 | 接收但不重排行；详情冻结；历史页由用户查看新记录 | 与图稿“鼠标下内容稳定”一致，不按推送替换详情对象 |
| 总数不可用 | 明确显示未知/暂不可用，不伪造页数 | 准确总数的执行预算仍需 T-03 核定 |

以上缓冲值为既有子计划的评审起点，不是已通过压测的容量结论。可以确认产品方向和初始值，正式保护参数仍需技术验证；调参若改变用户可见保证须重新确认。

**确认栏：** 待确认；分页 A / B；自动刷新开 / 关；推送和缓冲参数：待确认。
**影响：** BE-05/07/10、FE-04、BC-09/13/24/25、FC-04；来源为后端 BE-10、前端 FE-04。

### D-06 保留策略、缓存快照与默认值

**要决定：** 原方案的建议值是否作为新配置基线；不是批准对已有数据执行清理。

| 子项 | 既有方案建议 | 你的决定 |
| --- | --- | --- |
| 正常保留天数 R | 7 天；预设 1/3/7/30 天及自定义正整数 | 待确认 |
| 额外宽限 G | 3 天，允许 0 | 待确认 |
| 详情文件参考大小 T | 1 GiB，即 1073741824 bytes | 待确认 |
| 快照覆盖周期 | 5 分钟，允许正 duration | 待确认 |
| 清理时间与日期 | 服务器时区每天 01:00 调度，统计/详情按 UTC 日 | 待确认 |
| 缩短保留范围 | 后端预览影响并让用户确认，保存只修改策略 | 待确认 |
| 快照/详情 enable 等其他新 schema 默认值 | 图稿和 YAML 片段是示例，尚不足以认定全部默认值 | 由 T-01 列出完整候选后确认 |

推荐沿用上述建议。`S > T` 时保留 R 天，否则保留 R+G 天，包含当前 UTC 日；等于 T 仍享宽限，不能为了压到 T 删除有效期内的数据。统计与详情共用单调水位，增大期限不恢复已删数据。

保留自定义天数上界、查询分段/超时、时区识别异常、容量传输精度和快照恢复预算尚无最终值，分别由 T-01/T-03/T-04 核定。不能把旧 31 天查询上限继续隐藏保留，也不应现在随意填写一个没有测试依据的新上限。

**确认栏：** 待确认。可以逐项指定 R/G/T/周期；未确认的其他默认值不自动采用图稿数值。
**影响：** BE-01/04/06/08、FE-07、BC-01/07/11/21、FC-07；来源为原后端方案第 6 节。

### D-07 配置路径与 SecretRef 可见范围

**要决定：** 是否接受比现有只读 API 更明确的配置来源可见权限。

- **推荐 A：** 已认证管理用户只能读取/编辑已批准模块 DTO 中的源配置路径、环境变量名和文件引用，用于图稿中的表单；不新增角色管理。
- **备选 B：** 连引用来源也不返回。相关代理/文件来源只能通过部署配置管理，需要缩减对应 WebUI 编辑范围，不能让页面显示空值后覆盖原配置。

两种选择均禁止实际代理 URL 中的凭据、Secret 解析内容、密码 hash、session token、任意文件内容和全量 resolved config。`database/webui/work` 只读，只有 `logs` 可写。

“源配置路径可见”与“返回运行时派生绝对路径”不同；源值本身是否为绝对路径也必须在字段白名单中明确。此项不是任意文件浏览授权，URL 含敏感参数的字段也需逐项处理。

**确认栏：** 待确认；A / B；还需隐藏的具体字段：待确认。
**影响：** BE-07/08、FE-09/10/11、BC-12、相关配置 API；来源为总计划 D-07。

### D-09 界面主题与图稿外状态
