## 2. 产品与契约决策

### D-01 版本与前后端切换

**已确认：** 配置/API 主版本升级，不保留旧 WebUI 兼容。

实施使用 `version: 2`、`/api/v2` 和 `management-api-v2.yaml` 作为新契约命名；这是沿原推荐补全的版本编号，不是当前文件已改变。数据库 layout、缓存格式和 WS epoch 各自管理，不能复用一个版本号表达所有状态。

初始化、登录、登出、安全中间件、开发代理、OpenAPI 生成入口和新页面同批切换。旧路径返回明确未找到/版本不支持，不为旧页面增加兼容 DTO 或重定向体系。保留语义未变的 `/dashboard`、`/queries` 路由。

### D-02 保存、应用与待重启配置

**已确认：**

1. 启动时由配置构造各运行时对象。
2. WebUI 修改先进行程序级配置调整，加载成功后再更新配置文件。
3. 运行期间监测配置文件；外部修改不自动加载，WebUI 提示需要处理。
4. 可还原文件或处理其修改；WebUI 编辑保存以当前运行状态为基准覆写文件。
5. 尽量不停机，不把所有配置修改都设计成重启流程。

**实施解释：**

- 表单读取“当前活动配置的原始表达”，不是外部待处理文件，也不是丢失相对路径/继承/SecretRef 的 `ResolvedConfig` 反向序列化。
- “还原”指以当前活动配置恢复受管配置文件，不回滚当前 DNS 运行态。
- “修改”提供差异预览，再通过所属模块表单选择/调整外部值并显式应用；不增加整份 YAML 编辑器。尚未选入候选的外部值不会随普通表单保存偷偷生效。
- 文件存在外部变更时，普通 WebUI 保存须明确提示会覆盖未采用差异，并绑定所见文件版本；不存在差异时不额外打断正常保存。
- 外部文件中 `database/webui/work` 等本期只读字段变化可展示，但不能借差异处理绕过只读限制。它们仍作为启动配置处理。
- 日志 enable/level/path、详情开关和常规 DNS 配置纳入热更新；进程启动路径、管理服务自身绑定和无法无损复用的 socket 不承诺任意在线切换。

运行时和文件无法组成一次跨介质原子提交。“已应用但持久化失败”、崩溃恢复和外部并发覆盖的处理建议详见[专项计划](webui-management-config-runtime-plan.md)，不沿用旧方案“已保存但未应用”作为常规流程。

### D-03 资源改名与本期操作范围

**已确认：** 各模块 `name` 唯一，其他配置引用必须随改名更新。

- 唯一性按实际引用命名空间校验：listener、strategy、hosts、rule_set、client、proxy 各自唯一；上游和上游组共享 upstream 命名空间。不同模块无公共引用空间时不强制全仓名称唯一。
- 编辑保留 `originalName`，候选新名称与所有类型化引用一次校验和应用，不能全局替换字符串。
- 客户端 `name` 改为必填、唯一的管理键；保留单个唯一且普通编辑只读的 `client_id`，仅承担请求 ID 匹配及历史匹配归属。两者职责不同，不因名称改动重写历史 ID。这是在保留用户已审阅身份设计前提下对“各模块 name 唯一”的落实。
- 引用“最新 name”指新活动配置中的引用，不追写旧解析记录的上游来源、匹配事实或已在途请求。
- 本期仍是列表、新增、编辑；组成员/策略规则等子项可在所属资源内增删排序，不增加顶层批量删除。

### D-04 指标口径与在线客户端

**已确认：整体采纳推荐。**

| 项目 | 采用口径 |
| --- | --- |
| 请求计数 | 已通过入站基础校验并接纳进入 DNS 处理的请求；重试/single-flight 上游分支不重复算客户端请求 |
| QPS | 最近 60 秒请求数 / 60，单位请求/秒 |
| RPM | 最近 600 秒请求数 / 10，单位请求/分钟 |
| 趋势 | 最近 10 分钟共同时间轴；QPS 秒桶，RPM 分钟桶 |
| 在线客户端 | 最近 60 秒有请求；原始 ID 优先，无 ID 按有效 IP，键类型域分隔 |
| 缺数 | 暖机、观测缺口、采样失败明确标识，不能填零冒充 |
| 内存 | 进程 RSS，API 用 bytes，UI 统一 MiB |

在线身份与已配置客户端数量不同，也不依赖详情开关。容量与采样保护由 T-05 核定。

### D-05 分页、自动刷新与实时缓冲

**已确认：采用 A 及推荐默认行为。**

| 项目 | 采用值/行为 |
| --- | --- |
| 历史分页 | opaque cursor 前后翻页、页大小；不提供任意页码直跳 |
| 自动刷新 | 解析记录默认关闭，开启后订阅 |
| 推送周期 | 服务指标每 1 秒；已提交解析记录每 1 秒合批 |
| 后端 replay | 60 秒、5000 条、8 MiB，先达到者为上限 |
| 前端缓冲 | 500 条或 2 MiB，先达到者为上限 |
| 浮层/历史页 | 接收但不重排行，固定详情，显式查看新记录 |
| 缺口/总数未知 | 明确 resync 或未知状态，不承诺无限回放，不伪造总数 |

上述数值是确认的初始配置基线，不是已通过压力测试的容量结论；隐藏连接/帧保护仍由实施者核定。

### D-06 保留策略、缓存快照与默认值

**已确认：** R=7 天，G=3 天，T=1 GiB（1073741824 bytes）；快照周期 5 分钟；服务器时区每天 01:00 清理，数据按 UTC 日。

`S > T` 保留 R 天，否则保留 R+G 天，包含当前 UTC 日。预览并确认可能缩短范围的变更；保存只是让新策略生效，不立即删历史。共同水位单调前进，期限延长不恢复已删除数据。

快照/详情 enable 等未在原推荐中明确的默认值、天数上限及恢复预算由 T-01/T-04 补齐，不从图中演示值推断。

### D-07 配置路径与 SecretRef 可见范围

**已确认：** 已认证 WebUI 用户全部按管理员处理，不新增角色/权限管理功能。

沿原表单范围返回白名单源路径、env 名称和 SecretRef file 引用；管理员身份不等于开放任意文件读取。实际 Secret、代理凭据、password hash、认证 token 不进入配置/session/业务投影；不发送全量 resolved config。`database/webui/work` 本期只读，`logs` 可编辑。

2026-09-08 用户追加确认：登录后的业务接口只使用 `Authorization: Bearer <token>`，WebUI 管理 token 不放 URL query，不以 Cookie 作为业务鉴权后备。为保留页面重载后的登录恢复，访问凭据只存在前端内存；独立 HttpOnly Cookie 仅用于同源 POST 刷新，初始化/登录/刷新成功响应是返回 access token 的唯一例外。实施与验证边界见[Management 实现](../implementation/backend/management.md#p1-bearer-业务鉴权2026-09-08)，本项不授权提前开发 BC-24/25 WS。

### D-10 旧配置、数据迁移与回退

**已确认：** 当前开发阶段无正在运行的服务，允许重大破坏性变更，不需要旧配置、旧数据、旧逻辑兼容。

取消旧配置映射预览、多 ID 拆分、旧 SQLite 流式搬迁、legacy 身份/统计兼容、旧版维护回退演练。改为新 schema/新数据布局直接初始化、新版重启可读及废弃代码退出。

发现旧格式可明确拒绝并要求指定新开发目录，不静默转换或清空不明路径；这属于边界校验，不是兼容支持。允许破坏性设计不等于本轮直接删除本地文件。新格式自身的 journal、快照与分片故障恢复继续保留。

### D-11 验收平台、规模与性能门槛

**已确认：** Windows 本机为本轮验收平台；Linux 为最终运行目标，平台特有代码可以实现，不要求专门验证其他平台，也不因此阻塞交付。规模约 10 个客户端，DNS 并发不高。

主目标为缓存命中时 DNS 主链路耗时 **2ms 内，不包括与客户端的 I/O**。测量采用预热后的 release 构建，在 canonical query 进入真实 DNS core 至 response 返回处计时，包含该边界内的策略/缓存/非阻塞观测开销，不包含 socket 收发和边界外编解码。不能只测 cache map lookup。

不擅自把要求改成“平均 2ms”或“P99 2ms”：报告样本量、命中率、P50/P95/P99、最大值及超过 2ms 的样本；存在超出时说明原因并由用户接受偏差，不默认算通过。不追求超高 QPS、跨平台性能对齐或长时间压测指标。

设计保留请求快照、短锁、共享连接、有界队列/缓冲、批写和背压，便于提高负载；不据此新建分布式系统、过度分片或无依据的复杂调度。

本轮请求是重订计划，不是开始编码。方案实施启动后，每个完成最小验证的语义检查点即精确提交，中文 Conventional Commit，并报告 hash、范围及验证；不必对已经授权阶段内的每次 commit 重复询问。
