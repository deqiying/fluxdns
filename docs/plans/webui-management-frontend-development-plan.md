## 1. 目标与基线

将现有七个只读管理页重构为图稿中的 12 个一级模块，配置类使用定制化二级弹窗，服务/记录/进程类保持观测职责。现有初始化、登录、登出与会话保护继续保留。

复用 [package.json](../../frontend/package.json) 中的 React、TypeScript、Vite、Ant Design、Router、TanStack Query 和既有测试体系，沿 [app/modules/shared](../architecture/frontend.md) 分层实施；不为配置查询额外建立全局数据 store，不手工维护生成类型，不用一份通用 JSON/YAML 编辑器覆盖所有表单。

2026-09-07 P0 已提供 v2 生成类型、12 个路径/模块映射、草稿/操作状态和客户端编辑白名单，事实见[应用实现](../implementation/frontend/application.md#能力与证据)。API client、代理和业务页面仍未切换 v2；后续不重复定义契约。Vitest/fixture 浏览器不等于真实后端或生产内嵌验收。

2026-09-08 FC-01 已接入[内存 Bearer 与专用 Cookie 刷新](../implementation/frontend/application.md#p1-bearer-接线2026-09-08)，并完成[12 路由壳层、浅色主题、响应式导航和旧路径 404](../implementation/frontend/application.md#p1-应用壳层2026-09-08)。FC-02 已交付[配置 client、operation 回读、版本化 query key、精确单位/继承/variant helper 与表单容器](../implementation/frontend/application.md#p1-配置交互基础2026-09-08)，FC-16 已交付[提示/差异/还原与同步重试基础](../implementation/frontend/application.md#p1-外部配置变化基础2026-09-08)。BC-30 正式路由就绪后，二者进一步接入 AppLayout 的 30 秒可见性轮询、全局失败/变化提示、双 revision 差异、确认还原和原 operation 持久化重试。FC-14 已提前接入[系统运行状态](../implementation/frontend/application.md#p1-系统运行状态2026-09-08)，直接消费 BC-23 的 v2 进程指标并复用 v1 基础信息。真实认证回归、后端文件联合验证、fixture 浏览器验证和 MSW/jsdom 验证分别记录，不互相替代；其余九个未就绪入口不加载演示业务数据。FC-01/02 的本轮全局接线已完成；FC-16 的组合采用和普通保存覆盖确认仍依赖 FC-05 至 FC-13，不在未授权 P3 前伪造入口。

图稿中数值、地址、健康提示、分页总数和按钮均为演示；正式页面必须使用后端已支持且可追溯的值，不能把图稿内容复制为生产默认数据。

## 4. FE-01：应用壳层与导航

### 开发步骤

1. 将菜单组织为图稿中的监控、DNS 管理、系统三组，共 12 个一级入口；“上游组”只是 DNS 上游页 tab，不增加第 13 个菜单。
2. 保留初始化与登录 guard、懒加载、错误边界、404、登出和 setup 竞争处理；目标 API 版本变更同步认证和开发代理。
3. 路由方案按[决策清单 D-01](webui-management-decisions.md#d-01-版本与前后端切换)确认；完整路由表由 T-02 核定，系统配置/进程状态使用不同路径，并测试深链接刷新。
4. 不维护旧 WebUI 路由兼容；删除被替代入口及依赖，未保留 URL 返回正常未找到页面。仍被新页面复用的模块不因目录同名整目录删除。
5. 设置页面、列表、表单、状态色、间距、字号和弹窗尺寸的统一 token。以浅灰导航、白工作区和克制的蓝色主操作为基准，状态使用额外中性色/警示色区分。
6. 壳层管理导航、会话、整体布局及一份轻量配置同步提示，不加载全部模块数据。外部变化提示可在任何页打开处理工作区；服务状态不增加无关模块摘要。
7. 定义内容区与表格的稳定宽度、溢出滚动和窄屏导航；禁止通过缩放整个 1600 像素画布适配手机。

### 验收

- 十二入口、激活态、tab、直接 URL/刷新/返回、未认证和 404 正确。
- setup 未决时不提前请求受保护数据；401/登出能取消请求并清除旧用户数据。
- 页面无营销 hero、嵌套卡片或大面积装饰；图稿中的品牌与工作区层次保留。
- 桌面与窄屏无文字互盖，图标按钮有可访问名称；新图标优先评估与 Ant Design 一致的既有依赖可用性，不手绘整套图标。

## 5. FE-02：配置表单与跨端状态基础

### 5.1 数据所有权

| 数据 | 所有者 | 约束 |
| --- | --- | --- |
| 配置/列表/状态快照 | TanStack Query | query key 包含模块、资源键、过滤、页/cursor 和版本上下文 |
| 编辑草稿 | 弹窗局部 form state | 固定 originalName、active/file revision；不因 refetch 或外部文件变化覆盖草稿 |
| 会话 | 既有 AuthProvider | 不在表单或 WS 中维护第二套 token/session |
| 实时连接与订阅 | 按实际消费者管理的有界连接能力 | 页面订阅可独立关闭；登出/401/卸载释放所有相关数据 |
| 查询浮层及新增缓冲 | queries 模块 | 固定记录 ID、目录显示快照和有限新增缓冲，不入全局 store |
| 外部差异草稿 | 配置变化工作区局部状态 | 使用同一份差异版本和各模块类型化表单，退出确认；不新建全局配置 store |

当前活动配置的原始表达、生效值和继承来源分别呈现；外部文件值只在差异工作区出现。不要把 resolved 值回填为显式配置，也不要把清空一概序列化成 `null`。

### 5.2 表单基础工作

1. 复用 Ant Design 的 Form/Modal/Select/InputNumber 等能力，提供一致的焦点、滚动、错误定位和关闭确认；各领域仍使用定制化表单。
2. 建立字节与 MiB/GiB、duration、IP/CIDR、资源引用和覆盖项的共享转换/展示 helper；转换与业务规则分离。
3. 根据 schema 控制整数精度、单位与上下界；超过 JavaScript 安全整数的值不能先转 Number 再丢精度，按正式 DTO 使用受限数值或十进制字符串策略。
4. 类型切换提示将删除的不适用字段；只将当前 variant 的合法 payload 提交，隐藏字段不能残留进请求。
5. 请求错误保留安全 request ID 与字段路径；422/400 的具体选择以正式 OpenAPI 为准，不在 UI 散落状态码猜测。
6. API 写入不自动重试；保存中防重复提交。请求携带稳定 operation_id，HTTP timeout/断线先查询其结果及 revision；“重试文件同步”只调用专门同步能力，不重放创建/改名。
7. 配置列表的搜索/过滤/分页由后端或完整的有界配置集合正确执行，不能仅搜索当前显示页。资源引用选择器支持加载、空态、已删除引用和当前不可选项。

### 5.3 编辑状态机

```text
读取活动配置 -> 有修改 -> 预校验 -> 影响/外部覆盖确认
                                -> 应用中 -> 文件同步中 -> 已应用并同步
                                -> 应用失败/补偿异常
                                -> 已应用，文件未同步 -> 重试同步
                                -> active/file revision 冲突
                                -> 结果待确认 -> 查询 operation
```

- 打开失败提供重试，不打开空白表单让用户覆盖未知配置。
- active/file 预期版本与原 name 来自编辑快照；名称输入变化不改旧键。
- 冲突显示当前配置已变化，可重新加载或取消；保留本地草稿供比较，不自动“合并后强制保存”。
- 应用失败保留草稿；一旦确认运行时已应用，即更新活动配置缓存，即使文件同步失败也不能继续显示旧活动值。未同步警示保留；定时任务尚未运行与配置未应用分开显示。
- 关闭按钮、`Esc`、遮罩点击、路由离开遵守同一脏表单确认；保存中不允许不明确的二次提交或关闭导致假取消。
- 弹窗限制高度，内部滚动、标题/操作区可达；嵌套子项编辑避免多层弹窗互相抢焦点。

### 5.4 数据刷新与关联失效

每次保存完成使目标模块、引用选项和受影响概览失效；上游改名还涉及组/策略引用，客户端名称变更使后续客户端显示重新取目录，R/G/T 变更使保留状态和默认查询窗口重新读取。不能刷新所有 query 来替代准确失效，也不能让这些失效覆盖正在查看的记录/编辑草稿。

### 5.5 外部文件变化工作区

1. 壳层订阅轻量配置状态，HTTP 轮询可先行，WS 通知后仍回读权威快照；不依赖解析记录自动刷新开关。
2. 提示文件已变化/缺失/不可读及未同步状态，提供查看、还原、修改并采用；关闭提示不等于处理完成。
3. 差异只展示后端白名单字段和来源版本；Secret/hash 值不可见。无效 YAML 显示受限错误，不能用空表单覆盖未知内容。
4. “还原文件”确认后仅同步当前活动配置，不提示 DNS 已回滚或重启。
5. “修改并采用”复用各模块表单，支持组合依赖资源、明确旧名映射，一次提交合法候选。只读字段不能被勾选带入；未采用差异将被还原，确认中列明。
6. 普通表单保存遇到外改时，告知将以活动配置加本次编辑覆写文件；未确认不提交，确认绑定当前文件版本，再次外改仍冲突。
7. 未同步时显示风险及重试动作，阻止叠加配置变更，不禁用 DNS 观测页面。会话失效清除草稿和订阅，不把敏感草稿持久化到浏览器。

### 验收

使用 MSW/Testing Library 覆盖表单状态、operation 回读、已应用未同步、二次外改、还原/组合采用/取消、草稿保护、单位和继承；Windows 真实文件联调覆盖同样核心流程。fixture 来自 BE-01，生产不得兜底 mock。

## 6. FE-03：服务状态

### 开发步骤

1. 替换旧 dashboard 内容，只保留内存、最近 1 分钟平均 QPS、最近 10 分钟平均 RPM、在线客户端及合并趋势图。
2. 使用 BE-09 已签定的单位、窗口和采样时间；两个页面内存同为进程常驻内存，数字格式与 MiB/MB 选择一致。
3. HTTP 初始化快照后接指标订阅；组件不自行用记录列表数量、配置客户端数或当前 QPS 推算其他指标。
4. 趋势共用最近 10 分钟时间轴，QPS/RPM 分别使用请求/秒和请求/分钟轴，零基线与不同线宽/标记/图例保留。选中时刻浮层提供各自实际采样区间。
5. 不跨缺口连线，不为了平滑去掉峰值；图表库可按 D-08 的常见依赖授权选择，说明复用价值并验证。
6. 处理 warming、正常零流量、采样失败、部分窗口和陈旧数据。正常界面不显示 WS 通道/连接状态；数据过期以业务数据异常反馈，不能永远显示旧数值。
7. 页面隐藏/恢复按统一订阅策略暂停显示更新并在恢复时取新快照；重连期间不将时间轴用零值补满。

### 验收

fixture 与受控真实流量分别校验口径、单位、峰值、缺口与在线数量；浅/深图布局一致、曲线和非颜色标记可辨。键盘/触屏可读取图表数值；视口变化不遮挡坐标/图例。FE-03 在 BE-10 真推送接入前只能标为待联调。

## 7. FE-04：解析记录与稳定详情

### 7.1 列表与查询

1. 保留时间、请求、当时匹配/当前名称、结果、来源、耗时的两行信息层级；默认事件时间倒序，稳定记录 ID 用作 row key。
2. 主筛选包含域名、匹配客户端、原始 ID、原始 IP、协议、来源和日期；响应码/结果状态进入高级筛选，不删除旧已支持过滤。
3. 默认范围读取统计 R 天，允许显式选择后端实际仍保留的历史；宽限数据标识与后端返回一致，不能假设选 30 天就必有 30 天数据。
4. 查询参数规范化后进入 query key；过滤变化重置 cursor、详情和新增缓冲，取消旧请求。提交序列 cursor 不混入历史排序 cursor。
5. 按 D-05 实现前后翻页、页大小、准确可用的总数。总数缺失/查询超时显示其真实状态；不伪造页码总数，不以当前页过滤模拟全量搜索。
6. 旧排序/过滤只有不破坏新契约时保留；非首页、非默认倒序或固定历史范围下，实时记录仅标记有更新，不强行插入改变当前页。

### 7.2 身份与结果展示

- 请求事实显示原始 ID/IP；无 ID 为“未传入”，不再实现旧版 legacy 数据读取/展示分支。
- 当时匹配显示历史 ID 及 ID/IP 来源；当前名称独立标识，配置删除后保留历史 ID，不按当前 IP 再匹配。
- 原始未知 ID 回退命中其他配置时同时显示两者，不能将匹配 ID 回填原始 ID。
- 来源第一行区分上游、缓存命中、过期缓存、Hosts/规则；缓存第二行保留实际生产上游，明确不是本次又访问了上游。
- 保留 `answers_truncated`、已保留数/总数、空 Answer、错误与两种耗时；qname/Answer 作为文本渲染，不拼 HTML 或伪造 wire。

### 7.3 非模态详情浮层

1. 锚定结果单元格，提供鼠标悬浮、键盘聚焦/确认和点击/触屏入口，不能只用不可交互 Tooltip。
2. 指针在触发项与浮层间移动保持打开，允许选择/复制文本；两者都离开后关闭，`Esc` 关闭并恢复焦点。
3. 固定记录 ID、当次记录内容和目录显示快照；重新请求详情时也以同一 ID 定位，不以行号取下一条。
4. 在视口边缘自动翻转/平移；限定宽高并内部滚动；不压暗背景，关闭保持列表滚动位置。
5. 列表已有足够详情时直接展示；确需详情读取时覆盖加载、失败/重试、记录已到期和超长 Answer。查看期间后台保留删除不能无声替换浮层内容。

### 7.4 自动刷新与有界缓冲

| 状态/事件 | 行为 |
| --- | --- |
| 默认进入 | 按已确认 D-05 默认关闭，先取 HTTP 快照 |
| 开启 | 基于快照边界订阅；显示连接中/正常/异常及最近更新时间 |
| 首页倒序且无浮层 | 去重后合并符合筛选的新记录，列表仍受 page size 限制；迟到记录按事件顺序处理 |
| 浮层打开或正在浏览历史页 | 继续接收但只进入待更新缓冲，固定当前页及浮层，显示待更新数量 |
| 关闭浮层 | 首页默认倒序可应用缓冲；历史页仍由“查看新记录”显式回到首屏 |
| 点击查看新记录 | 先关闭浮层，再清理旧分页上下文、取最新首屏/补齐快照并更新列表 |
| 缓冲溢出 | 上限采用决策清单 D-05 的初始方案并经 T-05 核定；停止积累正文并标记需重同步，不继续假装精确计数 |
| 断线/epoch 变化/cursor 过期 | 有界退避重连；可补齐时按 ID 去重，否则 HTTP 重取；当前浮层关闭前不强行换行 |
| 关闭自动刷新 | 取消记录订阅、停止该页自动更新；保留当前显示，清除等待应用的实时缓冲 |
| 切过滤/离页/登出 | 取消旧订阅和请求，清理缓冲；重新进入按新的参数初始化 |

缓冲数字是已确认的初始基线，不是无限保证。过载或未知缺口时显示“有新记录，需刷新”等非精确状态，不能丢掉数据后继续声称“仅有 N 条”。

### 验收

扩展 [QueriesPage tests](../../frontend/src/modules/queries/QueriesPage.test.tsx)：同毫秒、迟到记录、过滤组合、重复消息、竞态请求、分页、名称变更、浮层移动/复制/触屏、缓冲上限、重连补齐、详情过期、关闭刷新及认证回收。真实浏览器中用持续新增数据验证鼠标下记录和列表位置稳定。

## 9. FE-06：DNS 上游与上游组

### 开发步骤

1. 一个一级页面内使用上游/上游组 tab，各自搜索、筛选、列表、计数和新增入口；共用资源选择投影，不合成额外管理目录。
2. 编辑会话冻结 `originalName` 与 expected revision；名称可编辑，保存按旧名称定位，新名称在 payload 中；改名影响引用由后端预览返回。
3. 类型选择只覆盖当前模型的 hosts/doh/group。hosts 使用对应数据格式编辑；DoH 显示 address、bootstrap、connect IP、proxy、ECS 等真实字段。
4. 类型切换明确丢弃无关字段，重建当前合法 variant 并再次校验；未画出的 Hosts 上游分支必须完成，不能只实现 DoH 示例。
5. 组表单分别维护主/回退成员、模式和超时，支持成员增删/顺序。parallel/failover 不提交自定义权重；round-robin/load-balance 展开权重。
6. 空回退表示未配置，不构造空而必填的 fallback 对象；继承/缺省由 schema 决定。
7. 同名冲突、bootstrap/嵌套组环、成员不可用和改名引用失败保留草稿；不在前端用名称字符串替换所有配置。

### 验收

## 10. FE-07：DNS 配置与数据保留

### 开发步骤

1. 一级页分为缓存、TTL/ECS、统计数据、解析详情开关四个无外框分区，各自弹窗/受控操作，不提供整个 dns 对象自由编辑。
2. 缓存弹窗提供全局池开关、所有逻辑池共享内存预算、failure TTL、乐观缓存参数、快照启用/路径/覆盖周期及只读状态；不提供持久化配额。
3. 明确 UI 状态：全局池关闭不表示全部独立池关闭；快照关闭不关内存；快照损坏/恢复超时以冷启状态呈现，不误报 DNS 全部不可用。
4. TTL/ECS 补齐继承、禁用、自定义模式、TTL 范围及自定义网段等全部 schema 分支，序列化只保存显式选择。
5. 统计弹窗 R 使用 1/3/7/30 天及自定义正整数，G 允许 0，T 使用 MiB/GiB 到精确字节转换；R/G/T 同次提交。
6. 显示后端返回的服务器时区、每天 01:00 和 UTC 自然日口径；图稿 `Asia/Hong_Kong` 不是生产固定值。
7. 分开呈现正常窗口、目标保留天数、实际可查范围、已发布水位、下次预计截止日、详情大小与待回收空间，不自行计算权威清理结果。
8. 可能推进清理水位时先调用后端预览，展示实际影响后确认；参数/revision 变化使旧预览失效。保存策略不显示“历史已删除”，下一次执行重新采样可能改变估计。
9. 详情开关只提交 enable，不附带旧条数/天数/数据库路径；提交中禁用重复切换，失败恢复后端确认的值，不提前宣称已开启/关闭。
10. 缩短后再延长不承诺恢复已删除数据；空间参考不是磁盘硬限制，清理失败和写入/队列异常使用对应状态。

### 验收

单位往返、整数边界、两种阈值分支及等号、G=0、自定义天数、窗口超过 31 天、预览过期、确认取消、任务边界未生效、快照部分恢复、详情关闭统计仍工作。和 BE-06 联调一次实际截止日/可查范围变化。

## 11. FE-08：DNS 分流策略

2. 规则按明确顺序展示，支持添加、移除、单行编辑和上移/下移；可额外提供拖动，但键盘不能依赖拖动。

## 12. FE-09：Hosts 与规则集

### 12.1 Hosts

1. 列表区分 const/file、格式、更新计划与资源状态。
2. JSON 内联采用域名/IP 结构化行，保存前把同域名多 IP 聚合为合法映射；hosts 文本格式采用对应行级结构化编辑/校验，不出现整配置 YAML 编辑器。
3. file 来源只配置路径、格式、自动重载及间隔，不编辑文件正文；关闭自动重载按 schema 清理无关提交字段。
4. 切换来源丢弃不适用的有效字段，但在确认前可保留局部草稿；文件自动重载不显示为远程同步。

### 12.2 规则集

1. 补齐 const/file/remote 的源类型表单与 json/clash/dat 合法组合；按后端 parser 的真正能力限制选项。
2. JSON/行文本内容使用适配格式的局部输入与校验，不将 clash 行格式标成 YAML。
3. dat 作为二进制资源来源配置，不放进文本输入，不增加文件上传能力；非法来源/格式组合由后端再次校验。
4. remote 配置 URL、proxy、格式和更新周期；file 配置来源路径与更新；selector 及资源状态按读取契约展示。
5. 刷新失败但仍有有效旧版显示 stale 状态；首次加载失败、无可用版与被删除资源分别显示。不新增强制刷新、校验和或版本锁定按钮。

### 验收

两模块的来源/格式切换、重复域名、非法 IP、空内容、较大内联 body、自动更新开关、代理引用、远程错误、陈旧资源和首次失败。确认 UI 不修改用户文件正文、不泄露 URL 中的敏感内容。

8. 检查生产构建中无 mock worker/开发 fixture/source map 意外暴露，同源 API 路径、SPA 刷新和未知 API 分流正确；以真实内嵌 binary 再验证一次。

### 15.3 执行入口

实施时先按[环境规则](../rules/environment-usage.md)确认 [mise.toml](../../mise.toml)、Node/pnpm 来源与版本，不在验证中擅自改 lockfile。下列命令从 `frontend/` 执行，均为未来要求：

```powershell
pnpm run generate:api
pnpm run typecheck
pnpm run test
pnpm run build
```

文档检查从仓库根目录执行：

```powershell
pwsh -File .agents/skills/project-doc-maintenance/scripts/check-docs.ps1
git diff --check
```

本地服务、配置、截图、测试报告和运行时数据按[本地测试规则](../rules/local-testing.md)放入 `_fluxdns/`；生产打包与运行按[交付实现](../implementation/delivery.md)。未执行项明确标为未验证，mock 通过不替代真后端或浏览器。
